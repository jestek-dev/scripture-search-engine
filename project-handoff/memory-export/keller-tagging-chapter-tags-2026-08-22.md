# Keller tagging + chapter-tags-as-index assessment — 2026-08-22

**Jesse's two-part question (2026-08-22, gating the full-Bible summaries rollout — "let me ask before we get too far"):** (a) anything to learn from "the Keller brain system of tagging" for quick, efficient search with quality indexing; (b) should chapter/subdivision summary tags double as a search index — e.g. would tagging Genesis 4 with "blood" (Abel's blood crying from the ground, a 2-verse motif) help search?

**Keller identification:** "Keller brain" = Tim Keller's **Gospel in Life sermon archive** (gospelinlife.com; free since May 2023; 2,207 results; flat 56-topic taxonomy with counts; sparse ~3 topics/sermon "chiefly about" tagging; verse-range scripture anchors incl. discontinuous "Luke 15:1-2, 11-32"; range-intersection lookup). Ruled out: Keller Center (TGC), any Keller "second brain" PKM, Gary Keller, academic "Brain Tagging." **Confirmed by Jesse 2026-08-22 16:49Z** — he meant the searchable index of all Keller materials (Gospel in Life archive). Lessons: flat ~110-concept vocabulary is the right shape; invest in aliases/compound labels not hierarchy; sparse precision tagging; faceted counts as honest UI + curator coverage report; keep anchor-vs-mention link types distinct (Logos two-tier model); stable per-assertion IDs.

**Measured evidence (real engine 0.9.0 vs published v0.7.1 artifact + 108-concept fixture DB):** bare `blood` = concordance over 368 verses, Gen 4:10 ranks **#45** (below top-25); but `blood cries out from the ground` → Gen 4:10 **#1** (score 15.50, "Preached vocabulary" via Layer B verse_terms) and `abel's blood` → **#5** behind Heb 12:24 / Luke 11:51 / Matt 23:35 (defensible ordering, correct explanations). A chapter-level tag would only change the bare-word query, where all of Gen 4 outranking Lev 17:11 / Exod 12 = wrong scripture winning. Chapter-level rangeless tags would need a new weak signal family + budget changes + ENGINE_VERSION bump + gate regen — high cost, likely NO MEASURABLE EFFECT. "Blood" itself should not become a concept (concordance word; the Abel motif's future home is a verse-range anchor under a real concept via normal curation).

**Recommendation (delivered):** tags stay **display-only** for the rollout (no ENGINE_VERSION bump, per assessment Step 5). But rollout threads must capture three **required structured fields** per chapter/section, starting now: (1) per-tag verse-range refs as data (already pilot practice — formalize; these are candidate `concept_anchors` rows), (2) motif-candidates list — motif name + verse refs + 2-3 realistic query phrasings (raw feed for future concept packs AND golden fixtures), (3) section IDs aligned to the BSB/P5.6 spine. Cost minutes/chapter now vs redoing 1,189 chapters later. Ranking integration deferred, explicitly open: the sanctioned path is **P6.6·B7/J59** pericope theme labels → existing `concept_anchors`, fixtures-first, gauntlet-measured, ENGINE_VERSION discipline.
